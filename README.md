# Smart Budget

كيوسك عربي لطلب الوجبات بالعرض (Landscape). فيه مسارين من الشاشة الرئيسية:

- **احسب احتياجك:** الأفراد (عمر/وزن/طول/نشاط) ← الميزانية والوجبة ← اقتراحات وجبات على قد السعرات والماكروز والميزانية ← طلب.
- **المنيو:** تصفح كل الأصناف واطلب مباشرة.

بعد الطلب بيطلع بون (QR) ويدفع العميل عند الكاشير. للكاشير والأدمن شاشات خاصة، وأزرار دخولها السريع في الرئيسية مقصودة لعرض المشروع.

## التشغيل

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

افتح `http://localhost:3000`.

```powershell
pnpm test        # اختبارات الحسابات والترشيح ومسارات الشاشات
pnpm typecheck
pnpm lint
pnpm build
```

### إعدادات البيئة

انسخ `.env.example` إلى `.env.local` وأكمل (الرابط والمفتاح العام/publishable فقط، ولا تنشر الملف):

```dotenv
NEXT_PUBLIC_DATA_MODE=auto
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_OR_PUBLISHABLE_KEY
```

- `auto` (الافتراضي): Supabase لو الرابط والمفتاح موجودين، وإلا قاعدة العرض المحلية في المتصفح.
- `local`: بيانات العرض المحلية دائمًا. `supabase`: بيشترط الإعدادات، وفشل الاتصال بيظهر كخطأ ومفيش طلبات بديلة.
- بعد تغيير متغيرات `NEXT_PUBLIC_*` أعد تشغيل dev (أو أعد البناء).

الوضع المحلي بيحفظ في `localStorage` (`fathalla-demo-db-v1`) لنفس المتصفح بس، ومش بيتزامن مع Supabase.

## قاعدة بيانات Supabase

شغّل الملفات دي بالترتيب في SQL Editor على قاعدة الفريق **الموجودة** (مش لإنشاء قاعدة من الصفر):

| الملف | الغرض |
|---|---|
| `supabase/20261107_prototype_consistency.sql` | اتساق الطلبات: منع التكرار، التحقق من التوافر والسعر والميزانية، حساب الحصص، دفع ثابت |
| `supabase/20261108_meal_macros.sql` | أعمدة `carbs_g` / `protein_g` / `fat_g` لكل وجبة + قيمها + إعادة إنشاء `available_meals` |
| `supabase/20261109_menu_data_review.sql` | تصحيحات للمنيو الحالي (سعرات الكفتة والصواني وغيرها) بعد مراجعتها مع الوصفات |
| `supabase/20261109_menu_additions_optional.sql` | **اختياري:** عصائر وشاي وحلويات وسلطة كول سلو للسناك والعشا |

`backup_menu_before_20261109.json` نسخة من المنيو قبل التعديلات. الملفات القديمة (`SUPABASE_ALL_FIXES.sql` و`fix_*.sql` و`supabase_migration_update.sql`) تاريخية؛ لا تعد تشغيلها لأنها بتستبدل دوال بإصدارات أقدم. التفاصيل في [SETUP_AND_DEPLOY.md](SETUP_AND_DEPLOY.md).

### صور الصفحة الرئيسية

الصور على Supabase Storage (bucket عام `meal-images`، فولدر `home/`) علشان تظهر من أي جهاز. لرفعها أو تحديثها:

```powershell
node scripts/upload-home-assets.mjs
```

السكربت بيقرأ `.env.local` وبيرفع من غير ما يطبع أي مفتاح. أسماء الملفات متعرفة في `src/lib/home-assets.ts`.

## كيف الترشيحات بتشتغل

الحساب: BMR (Mifflin-St Jeor) × النشاط = الاحتياج اليومي، وحصة الوجبة (فطار 25% / غدا 40% / عشا 30% / سناك 15%). الماكروز المطلوبة 50% كارب / 20% بروتين / 30% دهون.

المحرك (`features/recommendations/domain/engine.ts`) بيبني اقتراحات منطقية:

- لازم وجبة أساسية؛ المشروب والحلو والسلطة إضافات (مشروب + حلو لا يزيدوا عن 30% من السعرات).
- الأكل مناسب للوقت (مفيش بشاميل على الفطار) والصينية على قد المجموعة (`meal-rules.ts`).
- كل فرد وجبة أساسية، أو 2-3 لو الأصناف صغيرة. الاقتراحات التلاتة بأصناف أساسية مختلفة.
- السعرات قريبة من الهدف، والكارب/البروتين/الدهون قريبة من المطلوب.

## تنظيم الكود

- `src/app`: الرئيسية، `plan/people`، `plan/budget`، `plan/results`، `menu`، `receipt/[id]`، `cashier`، `admin`.
- `src/components`: `home` (أبواب متحركة وشريط صور)، `people` (حلقة السعرات والعدّادات)، `layout` (الهيدر وشريط الخطوات)، `ui`.
- `src/lib/data`: مصدر البيانات (محلي أو Supabase)، العمليات المشتركة، والتحقق من الطلب.
- `src/features/nutrition/domain`: BMR وTDEE ونسب الوجبات والماكروز.
- `src/features/recommendations/domain`: المحرك وقواعد الوجبات وتوزيع الحصص.
- `src/features/planner/store`: حالة الطلب الجاري.
- `src/test/order-flow.test.tsx`: اختبارات مسار الشاشات (سلة ← بون ← دفع وفشل الدفع).
- `scripts/`: أدوات مساعدة (رفع صور الرئيسية).

## التصميم

- واجهة بالعرض، كل خطوة في شاشة واحدة، وكلام قليل.
- ألوان نبيتي/خردلي على خلفية كريمية، وأزرار لمس كبيرة، وخط IBM Plex Sans Arabic.
- الأحجام بالـ`rem` وبتتكيّف مع عرض وارتفاع الشاشة (لابتوب صغير لحد شاشة كيوسك)، وأزرار الإجراء الرئيسية ثابتة أسفل الشاشة.
- جرب على 1024×600 و1280×650 و1920×1080.

## حدود النسخة الحالية

الطباعة عبر حوار المتصفح (`react-to-print`) بمقاس 80mm، وليست تكامل ESC/POS مباشرًا. البون فيه QR بمعرّف الطلب فقط (من غير Code128 أو HMAC) ومفيش شاشة مطبخ مستقلة. الأسعار والسعرات والماكروز بيانات عرض وليست قياسات معتمدة من المطعم. ملفات `SMART_BUDGET_FATHALLA_MASTER_SPECIFICATION.md` و`DESIGN_SYSTEM_AND_UX_AUDIT.md` وثائق تصور قديمة وتحتوي ادعاءات ونتائج لا تعبّر عن الحالة الحالية.
